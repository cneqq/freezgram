# Freezgram API

The Android client calls https://gift.cneqq.com/freezgram/api/. Nginx serves badges.json directly and proxies only activity reports to Python at 127.0.0.1:8091. Activity has per-IP and global rate limits plus a concurrency limit. The public badge list can be cached for 60 seconds and requires no device attestation. The systemd service runs under a dedicated dynamic user.

- To grant or revoke badges, edit /etc/freezgram-api/badges.json on the VPS. Use {"users":[123],"channels":[456]} with positive numeric Telegram IDs (omit the -100 prefix for channels). Validate the JSON before replacing the file atomically. No service restart or APK update is needed. The app keeps the last valid list and checks for updates on foreground entry.
- To view unique active accounts, run /usr/bin/python3 /opt/freezgram-api/api.py stats on the VPS. The rolling windows are 24 hours and 30 days. Usage statistics are enabled by default. Accounts are excluded from future reports when the user turns statistics off in the app. Reports are deduplicated using a server-side HMAC; the raw ID is not persisted by this API. The server prunes inactive records hourly. Counts are approximate because reports are not authenticated by Telegram.
- The service creates its state and HMAC key in the systemd state directory. Preserve that directory when updating the service; replacing the key breaks deduplication across the change.
