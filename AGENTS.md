# Правила Freezgram

- Отвечать по-русски. Сохранять чужие и несвязанные изменения.
- После реализации и проверок по умолчанию **создавать коммит, делать push и запускать APK-сборку**. Это постоянное указание пользователя; отдельные команды на эти действия не требуются.
- Если пользователь говорит **«без билда»**, коммит и push выполняются, сборка не запускается. Для push-сборки использовать `[skip ci]` в сообщении коммита. Не запускать workflow вручную в таком случае.
- `Personal release APK` автоматически запускается на push в `no-plugins`; ручной `workflow_dispatch` сохраняется. Не запускать вторую сборку того же коммита, если автоматическая уже появилась.
- После push проверять удалённый SHA и результат сборки; сообщать ссылку на запуск и APK либо конкретную причину сбоя. Не утверждать, что APK готов, до успешного завершения сборки.
- Рабочая ветка разработки — `no-plugins`. Не переносить изменения в `main` без соответствующей задачи.
- В коммит включать только относящиеся к задаче изменения. Не переписывать историю и не делать force-push.
- Проверять код до публикации. Чтение, обсуждение и аудит без изменений не требуют пустых коммитов и новых сборок.
- Не читать и не выводить секреты, ключи подписи и `.env`.
